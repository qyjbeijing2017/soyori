# AI 工具与预设子流程

当前状态整理：2026-10-13。项目整体背景见 [项目目标与决策](project-context.md)。下面先说明当前能力，其后的早期设计与验证记录仅作历史参考。

## 当前实现与边界

- Editor/CLI 共用 soyori-ai，提供 llm.auto、llm.openai、llm.anthropic、llm.local。远程使用 LangChain，本地使用 Transformers.js，Core 不引入模型 SDK。llm.auto 按有效 LLM_PROVIDER > 宿主供应商设置选择；auto 依次使用 model/apiKey 完整的 OpenAI、Anthropic，否则本地，失败不切换供应商重试。
- 连接逐项按步骤参数 > 有效环境 > 宿主连接 > 内置默认值解析，只有官方 Base URL 有内置默认值。CLI 环境为 --env > 系统环境 > env set 全局配置；网页环境按对话或文件覆盖全局，连接默认值来自设置。详见[环境手册](handbook/agents/environment.md)。
- input 接受文字或完整消息数组；提示词组合使用 template 步骤和 `$path$` 插值。新手流程用 chatIn → template → prompt → llm.auto → chatOut，见[快速入门](handbook/quick-start.md)。
- tools.execute 支持有接口定义的宿主函数及当前 imports 内的子流程，顺序执行请求，复用 Core。参数、可选允许列表和共享预算在执行入口检查；普通工具失败返回单项结果。批内暂停和逐项 Core trace 尚未实现。详见[工具调用](tool-calling.md)。
- 新建流程的五个外层步骤为 memory.init → llm.auto → memory.addAssistant → while → memory.save，完整上下文使用 memory 变量。循环内执行工具、memory.addTools、再次调用模型并追加消息。已有用户流程不自动改写，不内置摘要压缩。内置助手使用独立 assistant.json，可查询文档和工具、管理 Library 文件、创建和运行已保存流程，见[助手与浏览器运行](editor-assistant.md)。
- 当前本地模型为 onnx-community/Qwen3-1.7B-ONNX。浏览器 WebGPU + Q4F16 文件约 1.44 GB，需要 shader-f16；CLI 优先 WebGPU + Q4F16，初始化失败释放后回退 CPU + Q4（约 2.15 GB），生成失败不切换设备重试。下载取决于网速；缓存保留无需重复下载。加载可能需要几分钟，浏览器刷新或关闭重开、CLI 新进程均需再次初始化，同一次页面或进程内复用成功会话。
- 浏览器 script.run 与 CLI 共享模块契约，见[脚本与工作区](scripts-and-workspace.md)。尚未实现 Jev、多模态、skill 加载、通用外部工具加载、电脑目录同步、MCP、共享远程调试服务和原生封装；预设展示与升级机制仍待设计。手机与当前模型 CLI 跨设备推理仍需实测，模拟服务及布局测试不代表这些验证完成。
- npm 六包发布准备使用 MIT；项目已更名 Soyori，发布候选 scope 为 @soyori，权限尚待确认；本项目尚未发布，见[npm 发布准备](npm-release.md)。

## 历史设计与验证记录

> 以下保留早期决策的原始背景，包括已被替代的模型、参数和“尚未实现”描述；判断当前能力请以上面的状态和链接协议文档为准。

## 1. 核心原则：预设负责简单，节点负责能力

底层节点提供清晰、独立的能力；预设子流程负责把能力组合成容易使用的任务。新手无需先理解消息协议、工具调用 ID 或循环，就能运行一个 Agent；需要精细控制的用户可以展开和修改同一个子流程。

- 默认面向任务提供预设，例如“问 AI”“让 AI 使用工具”“判断并分流”，不把所有底层参数一次暴露给用户。
- 预设对外只暴露必要输入，内部仍是普通流程，不维护第二套隐藏的执行语义。
- 高级用户可修改子流程，加入人工确认、结果过滤、失败处理或外部执行步骤。
- 预设与内部步骤的执行结果和错误都应可查看，简单界面不能意味着不可调试。
- UI 采用渐进展示，手机也能完成配置和查看结果，不依赖画布、右键或复杂拖拽。

预设展示信息可包含名称、用途、输入说明、默认值及高级选项；具体元数据格式尚未确定。随工程保存可编辑的预设副本、更新时不静默改变工程行为，是建议方案，复制及升级机制待设计。

## 2. AI 接入的职责边界

| 层 | 职责 |
| --- | --- |
| Core | 唯一的流程语义与调度实现，处理字段、分支、子流程及 `call`；不引入供应商 SDK 或浏览器推理引擎 |
| 共享 AI 工具层 | 工具定义、参数校验、供应商适配、结果及错误处理；供 Editor 与 CLI 复用 |
| Editor / CLI 宿主 | 注册工具、获取凭据、管理资源生命周期，处理各自平台支持情况 |
| 用户子流程 / 预设 | 供应商切换、输出映射、Agent 工具循环及业务策略 |

优先复用 LangChain 的模型集成包，不自行重写已有的供应商协议适配。这里只采用需要的集成能力，不因此引入 LangGraph 接管现有 Core 编排。依赖版本、浏览器兼容性、包体积和许可仍需在实施时验证。

AI 工具不仅给 Editor 使用，CLI 也需要。具体共享包名称、目录及发布方式尚未确定；浏览器专属依赖不能无条件进入 CLI，Node 专属依赖也不能进入浏览器包。

## 3. 独立工具，不强制统一所有 AI 接口

底层保留不同能力的工具 key 和参数。以下名称仅为设计示意，不是已注册 API：

```text
llm.openai
llm.anthropic
llm.local
typesafe.decide
```

- OpenAI、Anthropic 各自保留适用的模型、消息、服务地址和生成选项，不假定所有参数都通用。
- 本地模型不要求 API Key，配置重点是模型选择、下载状态与运行选项。
- TypeSafe AI 的 Jev 是决策模型：输入状态与类型化问题，输出决策和概率等信息，不强行适配文本生成接口。类型正确不等于判断正确。
- 2026-10-09：远程连接改为步骤 inputs 中的 apiKey、baseURL、model，支持变量引用；直接填写的值随流程保存和导出，运行时传入可避免把密钥存为默认值。
- 两端支持同一工具时，应保持名称与契约一致；不支持或配置缺失时明确报错，不静默换模型或转为付费调用。

需要统一三种文本生成时，用户可创建接收供应商和消息的子流程，在分支中调用对应工具，将返回值映射成自己的统一输出。调用这个子流程就相当于一个统一节点，不需要平台再维护一套供应商切换机制。可提供示例预设，但不承诺换供应商后能力和效果一致。

## 4. 免费本地模型与当前优先级

先提供能实际生成结果的 AI 调用，暂不做操作 Editor 的内置助手。初步范围包括本地文本生成、OpenAI、Anthropic，以及组合固定文字与变量的提示词能力；Jev 是后续扩展场景，不代表本轮必须一起实现。

用户接受以 LFM2.5-350M 量化版作为本地候选，放弃以约 1 GB 以上模型作为当前默认方向。讨论时 Q4F16 权重约 255 MB；这是选型参考，不是最终总下载量、运行内存或永久不变的规格。2026-10-10 用户要求再次切换 LFM2.5-1.2B-Instruct 验证前置工具提示；当前浏览器 Q4F16 权重约 760 MB，CLI Q4 约 850 MB。模型版本、许可证和推理引擎支持需核实，并验证中文效果及手机、PC 的实际表现，不能把候选写成已经验证的默认模型。

本地模型按需下载并缓存，需要下载进度与失败处理；缓存可能被浏览器清理。免费指无需购买推理 API，不代表没有下载流量、设备内存和计算成本。浏览器与 CLI 的本地执行实现可以不同；浏览器可用不等于 Node 或所有手机都可用。

提示词组合能力应独立于供应商调用。节点类型、模板占位语法和 schema 尚未确定，不将讨论中的示意写法当作当前协议。

## 5. 流程作为 AI 工具

用户可以选择流程名或已有导入别名，将流程暴露为 AI 可调用工具。名称按现有流程作用域与 imports 规则解析，不改成全局流程注册表。

模型还需要工具用途和输入参数描述。优先利用流程、字段的现有说明；缺少参数类型、必填项等信息时补充工具契约，不要求整个流程运行时变成强类型。面向模型的工具名与内部流程引用可以映射，映射规则待实现。

执行边界必须遵守用户确认的三条规则：

1. **显式工具范围**：只执行当前允许列表内的流程；模型返回任意名称不能扩大权限。
2. **调用数据隔离**：明确传入参数和返回输出，不默认把父流程所有变量交给模型。沿用 Core 现有字段隔离和对象引用语义，不声称深拷贝隔离或安全沙箱。
3. **资源上限**：限制连续模型/工具调用及递归深度，防止无限循环；不能只靠用户在可编辑循环中自觉计数。具体预算作用域、默认值和取消边界待设计。

参数先按工具契约校验，再由运行环境桥接到 Core 的子流程执行。不能绕过 Core 重新实现流程解释器。

## 6. 单次模型调用与可编辑的 Agent 循环

底层生成工具完成一次模型调用，返回回复内容、工具调用请求和后续继续对话所需的信息。输入的“可用工具定义”与输出的“工具调用请求”是不同概念。

工具调用请求至少需要能表达调用 ID、工具名称和参数；这些是概念字段，不是已定稿的跨供应商 schema。不得只保留文本而丢掉供应商要求的消息、内容块或关联信息。

默认 Agent 预设子流程表达以下逻辑：

```text
调用模型
  → 没有工具请求：返回最终回复
  → 有工具请求：校验并执行允许的流程工具
               → 将关联调用 ID 的结果加入消息
               → 再次调用模型
```

用户可修改这个循环，也可输出工具请求给外部执行，再传回结果。平台提供执行流程工具、构造工具结果消息等辅助能力，避免用户手工拼各家协议。具体辅助工具、多个请求的执行顺序、失败结果及流式处理规则需在实施时明确，不预设并行或自动重试。

允许列表、参数边界和调用预算由实际执行入口校验，不能仅藏在可编辑预设里。外部执行路径也不能被宣称自动拥有平台的保护。

调试应能查看每次模型调用、工具名称与参数、对应子流程和工具结果。现有普通宿主函数调用仍算一步；工具桥接、循环预设及子调用追踪尚未实现，不能声称已经具备内部单步能力。
