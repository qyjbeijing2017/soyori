# Agent Plan：项目目标与决策

整理日期：2026-10-01。来源：本项目用户讨论及当前工作区代码。本文用于让新加入的 AI 窗口理解方向和已确认约束；实现状态是工作区快照，不代表已经提交、发布或部署。工作入口见 [AGENTS.md](../AGENTS.md)。

## 1. 项目为什么存在

让开发 AI Agent 更方便：用户和 AI 能组合工具、传递数据、逐步运行、观察结果并定位问题。用户预计 Agent 开发会更侧重工具本身，编排流程通常不复杂，因此优先降低工具接入、测试和联调成本，保持流程语言轻量。

同时考虑不熟悉程序设计的用户。用户表达“把这个位置设成这个值”时，运行器负责准备中间结构，不要求用户先声明类型或逐层构造对象。界面和错误应帮助理解执行过程。

产品成功的典型体验：用户或 AI 创建一个简短 Agent 流程，接入工具、填入参数，在手机或电脑上单步运行，查看变量和工具结果，再修改并验证。工具可以独立测试，不应为了测试一个工具必须跑完整个 Agent。

核心产品原则：**预设子流程负责简单，底层节点负责能力**。新手优先使用面向任务的预设，填写必要输入即可运行；需要时展开修改内部流程。预设复用同一套节点、子流程和调试机制，不是另一套隐藏引擎。默认界面最小化信息暴露，不要求先理解工程管理、供应商协议或 Agent 工具循环。

## 2. 用户已经确认的方向

| 主题 | 决策 |
| --- | --- |
| 编排方式 | 以逐步执行为基础，顺序步骤和嵌套 If/While 足够支撑当前方向；不考虑画布 |
| 重点 | 更方便开发 AI Agent，尤其是工具开发和调试，而不是扩展复杂编排能力 |
| 易用性 | 以预设子流程封装常见任务，底层节点保留能力；渐进展示高级配置与内部流程 |
| AI 接入 | 独立供应商/能力工具通过 `call` 执行，Editor 与 CLI 复用集成；不强制统一所有 AI 接口 |
| Agent 行为 | 流程可作为模型工具，工具循环和供应商切换由可编辑子流程实现；执行入口约束允许列表、调用数据与资源上限 |
| editor | 需要交互编辑流程；手机端也必须方便操作 |
| 多平台 | 优先考虑浏览器实现以降低初始成本，未来适配 Windows、macOS、iOS、Android |
| AI 联调 | 现有 AI 工具应方便读取项目上下文和执行信息，可考虑浏览器或 CLI 等接入 |
| 鉴权 | 完整鉴权可以后补，不作为第一版编辑体验的前置工程 |
| 数据写入 | 采用宽松自动创建/覆盖，避免普通类型冲突阻止用户完成设置 |
| 版本 | 当前尚无实际应用依赖，本次语法直接调整，保留 `schemaVersion: 1` |

“鉴权后补”不等于将可修改、执行项目的服务无保护地公开。何时开放远程访问、如何授权仍需在对应实施阶段确定。

## 3. 已实现的基础与边界

| 部分 | 当前工作区能力 | 边界 |
| --- | --- | --- |
| core | TypeScript/ESM；流程类型、校验、字段、运算、If/While、子流程、宿主函数 | 不内置模型、HTTP 或数据库 SDK，不负责文件与网络加载 |
| 调试内核 | `step()`、`run()`、`getState()`、`getStack()`、`setFields()`、根 `reset()` | 状态是实时视图；无历史恢复、通用暂停/取消协议 |
| CLI | `run/inspect/validate`，JSON/YAML、局部 imports、宿主函数、机器输出、trace、执行隔离与超时 | 不是持久开发服务，也没有让多个客户端接入同一运行的会话协议 |
| CLI 脚本 | 工作区已有内置 `runScript` 单文件脚本宿主能力 | 属于 Node CLI；不是浏览器运行能力，也不是通用不可信代码沙箱 |
| 数据语法 | `$` 引用、对象/数组路径、常量、`$$`、自动覆盖与 `append` | 不支持表达式或字符串插值；仍有明确校验与资源上限 |
| AI 工具 | 共享包提供本地/OpenAI/Anthropic 单次文本调用，CLI 与 Editor 均已注册；本地已实测桌面浏览器及 Node CPU | 无工具循环、流程工具桥接、Jev、多模态；手机与真实付费 API 尚未实测 |
| editor / 远程接入 | Web 步骤编辑与运行、AI 设置/调用表单、下载进度及 AI 取消 | 草稿仅在内存；无通用工具/外部 imports 加载、文件管理、助手、同步或 MCP |

运行输入和宿主返回值允许任意 JavaScript 值，不能把“能运行”理解成“能无损序列化或跨进程传输”。未来远程调试需设计值摘要和附件协议。

core 与 CLI 是总仓库下的独立 Git 子模块，使用 pnpm workspace 联合开发。保持内核与宿主分离，统一语义只实现一次。

## 4. 已落地的数据规则

2026-10-02 补充：记忆以流程变量保存，由子流程组织聊天和压缩。已实现通用 `storage.read/write/delete/list` 与 `tokens.count`，CLI 文件存储、用户配置和管理命令，以及 Editor IndexedDB 存储。不增加 namespace，用 `/` 分组的 key 区分数据；CLI 数据目录可配置，配置路径固定，更换目录不迁移数据。本地计数复用 tokenizer，远程仅提供显式估算；未内置压缩、对话记忆预设或存储管理页面。详见 [存储与计数](storage-and-tokens.md)。工程草稿和运行现场仍不自动保存。

详见 [变量、对象与数组方案](../agent-plan-core/docs/operands.md)，此处只记录关键决策和原因。

- `$count`、`$request.options.temperature`、`$messages[0].content` 读取变量或路径。普通字符串、数字、布尔值、`null` 是常量；`$$name` 表示文本 `$name`。
- 字面量对象/数组递归解析引用，键名不解析；每次执行新建字面量容器。初值、宿主输入、工具返回值及引用读出的值不再次解析。
- 所有写入位置统一使用路径。中间容器不存在或类型不适合时自动替换，不增加覆盖开关；已有兼容对象保留其他属性。
- `append` 追加一项，目标不是数组时替换成数组；值本身是数组时不展开。数组越界设置补 `null`，按当前实现限制路径索引和扩展量。
- 读取缺失路径返回 `undefined`，不会创建数据；非法语法、危险原型路径、只读目标和资源超限仍可能报错。
- 运行对象保持引用身份，属性修改对共享引用可见；整个字段替换不会替换其他字段持有的引用。
- 旧裸字段名引用已迁移为 `$`，不根据字段存在与否猜测字符串含义。

选择自动覆盖是有意的产品取舍：更少的前置知识和构造步骤。未来 editor 应展示修改结果，而不是重新引入强制类型声明或每次覆盖确认。

## 5. editor 基础工程与后续方案

`agent-plan-editor` 采用 React + TypeScript + Vite、普通 CSS，复用 core 的公开 API。当前已实现步骤编辑、逐步运行、数据与错误查看，以及三个 AI 调用工具。默认直接打开无需网络的示例，可添加 AI 调用；凭据只保留当前页面。尚无持久化、通用工具加载或 AI 助手。后续原生封装候选是 Tauri 2，也讨论过移动端 Capacitor；尚未定型。具体 AI 使用见 [AI 工具](../agent-plan-ai/README.md)。

建议界面：

- 桌面使用流程列表、参数面板和调试区域；支持插入、移动、复制、删除、撤销重做。
- 手机使用单列步骤、独立参数页、明确的移动操作；深层分支进入当前层级编辑，避免依靠拖线、右键或深度缩进。
- 工具选择后提供用途和参数说明、输入绑定、输出去向及独立试运行入口。
- 基础调试展示当前步骤、字段、调用栈、结果和错误；模型调用及工具内部事件需要宿主另外上报，当前一次函数调用仍算一步。
- 面向新手优先展示任务预设和必要输入，底层节点放进高级入口；支持按需查看、修改预设内部流程。现有页面不代表视觉方案已被确认。

editor 应持有编辑稳定标识，但当前运行协议的步骤没有 ID。稳定标识与流程结构路径如何映射，以及撤销与重排行为，需要在 editor 阶段设计，不能假定 core 已支持。

## 6. 当前确认的协作方向与历史方案

最新讨论采用以下方向；已实现部分以上述能力表和对应使用文档为准：

- 浏览器内虚拟工程作为工作副本，IndexedDB 自动保存；ZIP 导入导出为通用交换方式，支持的浏览器可关联用户授权的本地目录。
- GitHub/Gitee 是可选同步目标，通过平台 API 读写；第一版由用户自行申请个人令牌，不要求使用 Git，也不建设 Git 代理或 OAuth 服务。
- 当前先做流程里的 AI 调用，暂不做操作 editor 的内置助手。免费浏览器本地模型以 LFM2.5-350M 量化版为待验证候选，同时规划 OpenAI、Anthropic 接入和提示词组合能力；不以约 1 GB 以上模型作为当前默认方向。
- AI 接入优先复用 LangChain 的集成包，供 Editor/CLI 共享；不为模型接入引入 LangGraph 替代现有 Core。供应商独立工具、流程作为模型工具及可编辑 Agent 循环的决策见 [AI 工具与预设](ai-tools-and-presets.md)。其中工具名称、包划分和参数结构仍需实施时定稿。
- 内置助手、知识库和可编辑工程记忆是此前讨论的后续方向，不是当前 AI 节点工作的前置条件。
- 高级 PC Agent 通过 Git 或本地目录交换工程，直接调用 CLI 执行和测试；依赖 DOM/WebGL 的工具在真实浏览器测试。工程独立测试目录交换用例与必要结果。
- 不做运行会话持久化恢复；工程保存与运行现场分开。页面或进程销毁后重新运行，特殊对象不能强制序列化。
- 关联目录或仓库时明确导入/发布方向；保留未同步修改，检测冲突；已保存到浏览器与已同步分开显示。

以下为此前的共享开发服务建议，保留作为历史备选，不是当前第一版建设范围：

讨论建议增加一个开发服务，让 Web editor、CLI 和远程 MCP 适配共享项目及运行状态。MCP 是供 AI 使用的接口，可与普通网页 API 共用服务和执行逻辑，不需要复制一套内核。

预期可发现的信息：项目目的、流程定义与依赖、工具说明/参数/实现位置、编辑草稿、字段、执行位置、调用栈、错误和事件记录。提供摘要入口及按需详情，长记录分页，二进制通过附件访问；凭据不作为普通项目上下文公开。

预期动作：读取和编辑流程、校验、独立测试工具、创建运行、单步、继续、查看状态和订阅变化。重点是让 AI 能连接用户正在调试的会话，不是每次另起一个互不相关的运行。

建议服务层使用文档 `revision` 和运行 `runId`，处理并发修改和事件关联；运行绑定确定的流程版本，后续草稿用于下一次运行。它们是设计建议，不能与现有 core 的 `invocationId` 或 `schemaVersion` 混为一谈。

普通浏览器操作也要可行：使用语义化按钮、表单、可读取的状态与错误文本。外部 AI 产品的移动端、浏览器和插件能力会变化，接入时重新核实官方支持，不把聊天中某次查询当成永久保证。

若 AI 在远端浏览器或服务中运行，它与用户本地浏览器不共享 IndexedDB、Cookie 或 localhost。手机用户和 AI 要看到同一项目，需要可访问的服务和明确的同步/授权方案；仅有静态 editor 或本地存储不能实现共同联调。

## 7. 当前不主动扩展的范围

- 无限画布、任意连线、复杂并行与分支汇合。
- 自建完整 IDE、插件市场、全面类型系统或表达式语言。
- 第一阶段同时开发所有平台客户端和完整账号系统。
- 在没有明确需求时加入断点恢复、持久任务调度或多用户实时协作框架。

这些是控制当前复杂度的方向，不是永久禁止。只有实际需求出现时再调整，且不要为了未来可能需要提前改动核心协议。
