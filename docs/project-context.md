## 1. 项目为什么存在

2026-10-13 CLI 与运行环境调整（替代前面的 CLI thread/OS 规则）：run/validate 支持重复 --env NAME=value，仅本次生效；有效环境按 --env > OS 环境 > 持久全局配置，取消 CLI --thread-id 与输入 threadId 环境选择，CLI env 管理只保存全局。网页对话/文件作用域保持。共享 env.override 临时赋值、env.load 按调用流程相对路径读取约定 JSON，影响后续 LLM 与子流程，不持久保存、不自动加载文件；远端调用不能加载本地配置。原值运行环境工具不直接开放给网页助手模型。

2026-10-13 llm.auto：共享工具按有效 LLM_PROVIDER > 网页供应商设置选择，auto 时按配置完整的 OpenAI、Anthropic、本地排序；CLI 默认为 auto。明确指定供应商缺配置报错，失败不切换重试。复用现有输入输出和连接回退，远程/本地 token 默认值分别 4096/512。网页内置助手的 auto 模式使用此工具，环境参与选择。

2026-10-13 LLM 连接回退：OpenAI/Anthropic 三个连接参数逐项按步骤参数、当前有效环境、宿主连接默认值、内置默认值解析。环境名称为 OPENAI_MODEL/API_KEY/BASE_URL 与 ANTHROPIC_MODEL/API_KEY/BASE_URL。网页默认值来自连接设置，CLI 使用 --env > OS 环境 > 持久全局配置合并的有效环境；仅官方 Base URL 有内置默认值，模型与密钥缺失报错。省略/null/空白为未填写，错误类型仍校验。内置助手不将设置中的 model 固定写入步骤，以允许环境覆盖。

2026-10-13 助手环境管理：env.get 保留给流程执行，浏览器模型的工具列表和 tools.execute 不直接开放它。助手使用 env.list/inspect 查询有效环境，敏感项仅返回 missing/empty/set 状态；env.set 只写当前对话，新项默认敏感，不能降级已有敏感项。flow.run 继续允许真实凭证测试，读取发起运行环境的最新配置，并遮挡显式标记的输出和错误。无需操作编辑器或新增通用授权体系；这不是防止任意代码读取凭证的安全隔离。

2026-10-13 环境 UI 补充：环境编辑自动保存，取消独立保存按钮；对话与 Editor 的环境入口统一放顶栏右上角。Editor 运行测试允许当前文件环境覆盖全局，按文件 ID 本地保存，不随文件分发，不影响对话环境；子流程继承发起运行的环境，不读取自己的文件测试配置。

2026-10-13 环境与敏感值：用户确认环境按 thread 优先、全局兜底，共用于同一运行中的子流程；env.get 返回原值，不自动传播敏感性。字段 sensitive 是显示与导出元数据，运行语义和原值不变。用户显式标记需隐藏的字段；网页遮挡变量、记录与导出，CLI 遮挡 trace 和标记输出。环境独立于流程文件，本地明文保存，不是凭证加密或权限隔离。详细规则见 [环境与敏感值](handbook/agents/environment.md)。

让开发 AI Agent 更方便：用户和 AI 能组合工具、传递数据、逐步运行、观察结果并定位问题。用户预计 Agent 开发会更侧重工具本身，编排流程通常不复杂，因此优先降低工具接入、测试和联调成本，保持流程语言轻量。

同时考虑不熟悉程序设计的用户。用户表达“把这个位置设成这个值”时，运行器负责准备中间结构，不要求用户先声明类型或逐层构造对象。界面和错误应帮助理解执行过程。

产品成功的典型体验：用户或 AI 创建一个简短 Agent 流程，接入工具、填入参数，在手机或电脑上单步运行，查看变量和工具结果，再修改并验证。工具可以独立测试，不应为了测试一个工具必须跑完整个 Agent。

核心产品原则：**预设子流程负责简单，底层节点负责能力**。新手优先使用面向任务的预设，填写必要输入即可运行；需要时展开修改内部流程。预设复用同一套节点、子流程和调试机制，不是另一套隐藏引擎。默认界面最小化信息暴露，不要求先理解工程管理、供应商协议或 Agent 工具循环。

## 2. 用户已经确认的方向

新对话先进入空白草稿并保留所选 Agent，不创建 thread；首次发送用户消息时才分配 thread 并保存输入。Agent 选择在浏览器刷新后恢复，历史记录加载不自动创建空对话。

文件库优先保留 SVAR File Manager 原生工具栏、目录树、文件视图、新建/上传及响应式布局，仅补充流程入口、源码编辑和目录下载。只有 `.agentp.zip` 工程包自动解压，普通 ZIP 原样保存；目录/工作区下载统一使用该工程包后缀。代码输入与文件源码共用 CodeMirror 6，存储仍由现有 IndexedDB 工作区负责。

2026-10-09：Library 改为浏览器内文件工作区，IndexedDB 保存任意文件及目录，支持目录/ZIP 导入导出；JSON/YAML 必须通过 Core 校验才作为流程。CLI 和 Editor 共用 script.run 接口，仅用 code 执行 ESM 顶层代码，以全局 input 接收参数、result(value) 设置输出（最后一次调用为准，未调用返回 null）；外部脚本通过静态 import 和字面量动态 import 引入，CLI 可解析已安装包但不自动安装；完整边界见 [脚本与工作区](scripts-and-workspace.md)。此决策替代早期单文件脚本和 Library 平铺方案。


工具选择与执行统一开放当前作用域内所有可调用、带接口定义的目标，不按名称或 namespace 排除 LLM 或执行器自身。嵌套调用沿用共享执行预算；显式 tools 列表仍约束本次允许目标。

单个工具应职责单一、简单可理解：输入输出只服务于该工具本身的任务，不为方便后续环节而混入其他职责。工具执行只接收调用请求并返回执行结果；结果转消息、上下文拼接、记忆存储与压缩由后续独立的一组记忆编排工具承担，现由 memory.addUser/addAssistant/addTools 统一组装通用消息。tools.execute 的 tools 是可选高级限制，默认留空、不额外限制；仅返回 results，不提供 message/messages。此决策优先于文末早期工具接口记录。

| 主题 | 决策 |
| --- | --- |
| 编排方式 | 以逐步执行为基础，顺序步骤和嵌套 If/While 足够支撑当前方向；不考虑画布 |
| 重点 | 更方便开发 AI Agent，尤其是工具开发和调试，而不是扩展复杂编排能力 |
| 易用性 | 以预设子流程封装常见任务，底层节点保留能力；渐进展示高级配置与内部流程 |
| AI 接入 | 独立供应商/能力工具通过 `call` 执行，Editor 与 CLI 复用集成；不强制统一所有 AI 接口 |
| Agent 行为 | 流程可作为模型工具，工具循环和供应商切换由可编辑子流程实现；执行入口约束允许列表、调用数据与资源上限 |
| editor | 需要交互编辑流程；手机端也必须方便操作 |
| 多平台 | 优先考虑浏览器实现以降低初始成本，未来适配 Windows、macOS、iOS、Android |
| AI 联调 | 现有 AI 工具应方便读取项目上下文和执行信息，可考虑浏览器或 CLI 等接入 |
| 鉴权 | 完整鉴权可以后补，不作为第一版编辑体验的前置工程 |
| 数据写入 | 采用宽松自动创建/覆盖，避免普通类型冲突阻止用户完成设置 |
| 版本 | 当前尚无实际应用依赖，本次语法直接调整，保留 `schemaVersion: 1` |

“鉴权后补”不等于将可修改、执行项目的服务无保护地公开。何时开放远程访问、如何授权仍需在对应实施阶段确定。

2026-10-11：用户确认将默认本地模型替换为 Qwen3-1.7B-ONNX，Editor/CLI 共用固定模型版本和 Hermes 工具模板，默认关闭 thinking。浏览器 Q4F16 文件下载约 1.44 GB，首次使用在缓存内将权重外置以降低 ONNX 加载峰值；成功后保留 WebGPU 会话复用，失败、停止或释放时清理，不自动重试。Editor 运行库随应用同源打包加载。手机和新模型 Node CPU 兼容性仍需实测。

## 3. 已实现的基础与边界

| 部分 | 当前工作区能力 | 边界 |
| --- | --- | --- |
| core | TypeScript/ESM；流程类型、校验、字段、运算、If/While、子流程、宿主函数 | 不内置模型、HTTP 或数据库 SDK，不负责文件与网络加载 |
| 调试内核 | `step()`、`run()`、`getState()`、`getStack()`、`setFields()`、根 `reset()` | 状态是实时视图；无历史恢复、通用暂停/取消协议 |
| CLI | `run/inspect/validate`，JSON/YAML、局部 imports、宿主函数、机器输出、trace、执行隔离与超时 | 不是持久开发服务，也没有让多个客户端接入同一运行的会话协议 |
| 脚本 | CLI/Editor 共用 `script.run` 模块接口，支持宿主允许的模块加载 | 浏览器与 Node 加载能力不同；Worker 不构成通用不可信代码沙箱 |
| 数据语法 | `$` 引用、对象/数组路径、常量、`$$`、自动覆盖与 `append`；template 正文 `$path$` 插值 | 普通输入字符串不解析表达式或模板；仍有明确校验与资源上限 |
| AI 工具 | llm.auto 与本地/OpenAI/Anthropic 单次调用、流程工具桥接、显式工具循环与记忆模板 | 无 Jev、多模态和预设升级机制；手机、当前模型 CLI 跨设备推理与真实付费 API 尚待实测 |
| editor / 远程接入 | Agent 对话、Library 文件夹/ZIP/源码/相对 imports、步骤与变量表单、单步调试、内置项目助手和手册 | 无通用外部工具加载、电脑目录同步、共享远程调试或 MCP |

运行输入和宿主返回值允许任意 JavaScript 值，不能把“能运行”理解成“能无损序列化或跨进程传输”。未来远程调试需设计值摘要和附件协议。

core 与 CLI 是总仓库下的独立 Git 子模块，使用 pnpm workspace 联合开发。保持内核与宿主分离，统一语义只实现一次。

## 4. 已落地的数据规则

记忆以流程变量保存，聊天编排由普通步骤和子流程负责。已实现通用 `storage.read/write/delete/list` 与 `tokens.count`、CLI 文件存储和管理命令、Editor IndexedDB 存储，以及 memory.init/save 和默认记忆对话模板。不增加 namespace，用 `/` 分组的 key 区分数据；CLI 数据目录可配置，配置路径固定，更换目录不迁移数据。本地计数复用 tokenizer，远程仅提供显式估算；不内置摘要压缩或自动裁剪。详见 [存储与计数](storage-and-tokens.md)。Library 已保存的流程在刷新后保留，未应用的表单草稿和运行现场不恢复。

详见 [变量、对象与数组方案](../agent-plan-core/docs/operands.md)，此处只记录关键决策和原因。

- `$count`、`$request.options.temperature`、`$messages[0].content` 读取变量或路径。普通字符串、数字、布尔值、`null` 是常量；`$$name` 表示文本 `$name`。
- 字面量对象/数组递归解析引用，键名不解析；每次执行新建字面量容器。初值、宿主输入、工具返回值及引用读出的值不再次解析。
- 所有写入位置统一使用路径。中间容器不存在或类型不适合时自动替换，不增加覆盖开关；已有兼容对象保留其他属性。
- `append` 追加一项，目标不是数组时替换成数组；值本身是数组时不展开。数组越界设置补 `null`，按当前实现限制路径索引和扩展量。
- 读取缺失路径返回 `undefined`，不会创建数据；非法语法、危险原型路径、只读目标和资源超限仍可能报错。
- 运行对象保持引用身份，属性修改对共享引用可见；整个字段替换不会替换其他字段持有的引用。
- 旧裸字段名引用已迁移为 `$`，不根据字段存在与否猜测字符串含义。

选择自动覆盖是有意的产品取舍：更少的前置知识和构造步骤。Editor 展示修改结果，不重新引入强制类型声明或每次覆盖确认。

## 5. editor 基础工程与后续方案

界面分为 Agent、Library、Editor。Agent 可使用独立内置助手或用户对话流程，统一使用 chatIn/threadId 输入及 chatOut 输出；Library 保存文件和文件夹，支持 ZIP 导入导出、源码编辑和本地持久化；Editor 用步骤列表及变量表单编辑，参数用名称 + 输入栏编辑，自动推断 JSON/YAML/数字等类型。默认新建流程为可编辑的 memory 记忆对话和显式工具循环。

`agent-plan-editor` 采用 React + TypeScript + Vite、Mantine 组件及少量业务 CSS，复用 core 的公开 API。应用步骤或有效变量设置修改后，流程写入 Library 的 IndexedDB；对话展示记录和流程记忆独立保存，执行现场不恢复。首次使用本地模型需要下载，刷新后下一次使用重新加载；连接设置保存于当前浏览器 localStorage，步骤显式密钥会随流程导出。详见 [Editor](../agent-plan-editor/README.md)。后续原生封装候选是 Tauri 2，也讨论过移动端 Capacitor，尚未定型。

建议界面：

- 桌面使用流程列表、参数面板和调试区域；支持插入、移动、复制、删除、撤销重做。
- 手机使用单列步骤、独立参数页、明确的移动操作；深层分支进入当前层级编辑，避免依靠拖线、右键或深度缩进。
- 工具选择后提供用途和参数说明、输入绑定、输出去向及独立试运行入口。
- 基础调试展示当前步骤、字段、调用栈、结果和错误；模型调用及工具内部事件需要宿主另外上报，当前一次函数调用仍算一步。
- 面向新手优先展示任务预设和必要输入，底层节点放进高级入口；支持按需查看、修改预设内部流程。现有页面不代表视觉方案已被确认。

editor 应持有编辑稳定标识，但当前运行协议的步骤没有 ID。稳定标识与流程结构路径如何映射，以及撤销与重排行为，需要在 editor 阶段设计，不能假定 core 已支持。

## 6. 当前确认的协作方向与历史方案

最新讨论采用以下方向；已实现部分以上述能力表和对应使用文档为准：

- 浏览器内虚拟工程作为工作副本，IndexedDB 自动保存；ZIP 导入导出为通用交换方式，支持的浏览器可关联用户授权的本地目录。
- GitHub/Gitee 是可选同步目标，通过平台 API 读写；第一版由用户自行申请个人令牌，不要求使用 Git，也不建设 Git 代理或 OAuth 服务。
- 当前先做流程里的 AI 调用，暂不做操作 editor 的内置助手。免费浏览器本地模型以 LFM2.5-350M 量化版为待验证候选，同时规划 OpenAI、Anthropic 接入和提示词组合能力；不以约 1 GB 以上模型作为当前默认方向。
- AI 接入优先复用 LangChain 的集成包，供 Editor/CLI 共享；不为模型接入引入 LangGraph 替代现有 Core。供应商独立工具、流程作为模型工具及可编辑 Agent 循环的决策见 [AI 工具与预设](ai-tools-and-presets.md)。其中工具名称、包划分和参数结构仍需实施时定稿。
- 内置助手、知识库和可编辑工程记忆是此前讨论的后续方向，不是当前 AI 节点工作的前置条件。
- 高级 PC Agent 通过 Git 或本地目录交换工程，直接调用 CLI 执行和测试；依赖 DOM/WebGL 的工具在真实浏览器测试。工程独立测试目录交换用例与必要结果。
- 不做运行会话持久化恢复；工程保存与运行现场分开。页面或进程销毁后重新运行，特殊对象不能强制序列化。
- 关联目录或仓库时明确导入/发布方向；保留未同步修改，检测冲突；已保存到浏览器与已同步分开显示。

以下为此前的共享开发服务建议，保留作为历史备选，不是当前第一版建设范围：

讨论建议增加一个开发服务，让 Web editor、CLI 和远程 MCP 适配共享项目及运行状态。MCP 是供 AI 使用的接口，可与普通网页 API 共用服务和执行逻辑，不需要复制一套内核。

预期可发现的信息：项目目的、流程定义与依赖、工具说明/参数/实现位置、编辑草稿、字段、执行位置、调用栈、错误和事件记录。提供摘要入口及按需详情，长记录分页，二进制通过附件访问；凭据不作为普通项目上下文公开。

预期动作：读取和编辑流程、校验、独立测试工具、创建运行、单步、继续、查看状态和订阅变化。重点是让 AI 能连接用户正在调试的会话，不是每次另起一个互不相关的运行。

建议服务层使用文档 `revision` 和运行 `runId`，处理并发修改和事件关联；运行绑定确定的流程版本，后续草稿用于下一次运行。它们是设计建议，不能与现有 core 的 `invocationId` 或 `schemaVersion` 混为一谈。

普通浏览器操作也要可行：使用语义化按钮、表单、可读取的状态与错误文本。外部 AI 产品的移动端、浏览器和插件能力会变化，接入时重新核实官方支持，不把聊天中某次查询当成永久保证。

若 AI 在远端浏览器或服务中运行，它与用户本地浏览器不共享 IndexedDB、Cookie 或 localhost。手机用户和 AI 要看到同一项目，需要可访问的服务和明确的同步/授权方案；仅有静态 editor 或本地存储不能实现共同联调。

## 7. 当前不主动扩展的范围

- 无限画布、任意连线、复杂并行与分支汇合。
- 自建完整 IDE、插件市场、全面类型系统或表达式语言。
- 第一阶段同时开发所有平台客户端和完整账号系统。
- 在没有明确需求时加入断点恢复、持久任务调度或多用户实时协作框架。

这些是控制当前复杂度的方向，不是永久禁止。只有实际需求出现时再调整，且不要为了未来可能需要提前改动核心协议。

### 多对话与节点展示（2026-10-02）

Agent 支持新建和切换多个 thread，每个流程的会话列表、当前选择和聊天记录保存在浏览器中。新对话不删除旧记录。每轮传入 chatIn 和 threadId，原始对话按 threads/<threadId> 存入通用存储；流程自行决定是否读取历史和怎样保存记忆。旧版对话数据不迁移、不读取、不删除。Editor 调试仍使用流程原始初值。

Library 默认导出可读 YAML，仍兼容 JSON/YAML 上传。19 种基础节点按数据、文本、计算、判断、控制和调用六类着色；卡片优先显示节点名称或调用目标，说明作为辅助文本，参数与详细结果按需打开。


### 对话流程与精简界面（2026-10-02）

对话流程的唯一识别条件是 `fields.chatOut.output: true`，允许包含其他字段。Agent 传入用户文字，运行后读取 `chatOut` 作为回复：字符串渲染 Markdown，其余 JSON 值展示为 YAML 代码块。流程如何生成回复、保存记忆由流程本身决定。Agent 页面直接选择 Library 中符合约定的流程，保留多 thread 切换，运行中锁定切换。

Library 卡片仅展示流程类型、名称及编辑/对话/下载/删除图标，名称旁提供铅笔改名；长名称省略展示、悬停可看完整内容。Editor 用短节点名、分类图标及颜色，小字标注输入输出或条件；说明保留在编辑表单和标题提示中，最右侧铅笔打开编辑弹窗。

默认示例已切换为 text 接口。浏览器中旧的内置 `local-agent` 如仍使用 prompt/answer 且没有 text 字段，会通过普通 set 步骤接入 text，保留原有步骤和记忆；其他用户流程不自动改写，也不继续作为旧接口对话流程识别。


### 参数编辑与运行变量（2026-10-03）

参数和步骤参数统一为“名称 + 右侧输入栏”，自动推断 JSON、YAML、数字、布尔值和文本，保留引号表达纯文本的能力，不再要求手选类型。结构错误明确反馈，不静默使用旧值运行。变量的名称、说明和输入/输出标记按需展开。

取消独立运行数据页面，直接复用变量面板显示当前运行值。单步暂停时用户可填写/修改已声明变量，通过 Core 公开 setFields 更新当前现场，继续执行不重置进度；运行中的修改不写回流程初始值。默认值在变量弹窗修改并保存；外部始终为运行值。执行完毕保留值并可直接再次运行，仅重置恢复默认值；步骤结构更改清除进度，保留同名变量的运行值。


### UI 组件与国际化基础（2026-10-03）

Editor 接入 Mantine 9，统一绿色主题与 44px 基础触控目标。按钮、输入、选择器、参数输入、操作菜单、变量弹层和设置/改名弹窗复用组件库；保留三页布局、步骤列表及 Core 调试语义。旧原生控件样式不覆盖 Mantine 组件。后续优先使用库组件和主题配置，避免再手写同类交互。

国际化使用 i18next + react-i18next，默认简体中文，支持英文切换和本机语言偏好保存，更新页面 lang 属性；翻译资源随应用打包，无翻译服务依赖。现阶段以中文源文案为资源键，插值必须保留变量占位符，新增文案同步维护两种资源并运行完整性测试。动态流程名称、参数键、提示词、聊天内容及工具返回内容不翻译；工具/模型的原始错误与进度消息可能保留源语言。切换语言不重建流程、聊天或调试状态。

### 抽屉导航与移动编辑（2026-10-03）

顶部统一 Agent / Library / Editor 悬浮标签；抽屉管理跨流程的 thread、新对话与底部设置，选择 thread 回到 Agent。手机仅支持按钮及遮罩关闭，暂不启用滑动手势；桌面为可折叠侧栏。顶部移除用户/设置入口，尚无账号系统。本地模型与语言设置集中在独立设置页面（远程连接配置于 2026-10-09 移至步骤），首次运行本地模型的下载许可默认开启。

Agent 始终提供独立内置本地 Agent，删除 Library 流程不会移除它。输入框分为文字输入和下方 Agent 选择/发送工具栏；语音、多模态仍未实现。Library 和 Editor 去掉大标题及描述。

Editor 两端统一变量在上、步骤在下，底部固定运行/下一步/撤销，手机以图标呈现。变量和步骤均可通过手柄排序，嵌套步骤限制在所属分支内。新增即打开弹窗；步骤弹窗合并设置、输入、输出、删除，取消复制入口；变量设置和普通编辑值自动保存，取消单独保存按钮。运行暂停时编辑变量仍只改变 Core 现场；不将调试数据写回初值，不增加恢复语义。

### 设置与对话管理补充（2026-10-03）

设置只从抽屉底部进入，桌面和手机均为带返回入口的独立页面，采用常规、本地模型、OpenAI、Anthropic 分组，不折叠内容；返回保留原页面与草稿。抽屉使用侧栏折叠图标。

每条 thread 右侧提供删除图标，确认后持久化删除聊天记录；不删除流程或流程自行管理的其他存储数据。删除当前 thread 时选择剩余 thread；删掉最后一条 thread 后保留空列表；显式新建或首次发送消息时才创建新的 thread 与 threadId。运行中禁止删除。

### 紧凑列表与删除修正（2026-10-03）

Library 搜索在左，数量/上传/新建在右，共用一行；手机隐藏数量和按钮文字，保留圆形图标按钮。流程标题右侧显示类型标签，卡片中部预留说明，右下角集中显示操作。点击卡片进入 Editor；名称与说明通过操作按钮打开弹窗修改。变量区取消整体大卡片，变量以无卡片底板的紧凑行展示，保留拖拽、内联值与弹窗设置。对话行整行悬停着色；确认删除弹窗层级高于手机抽屉。纯图标按钮使用圆形底板，颜色与交互含义不变。

对话输入框占满输入区并左对齐；右侧 Agent 选择统一使用带搜索的组件弹窗。Library 桌面搜索限制宽度，上传/新建按钮默认透明，卡片两行之间不加分割线并保持紧凑间距。步骤拖动手柄放在步骤卡片内部，底部运行工具栏在手机与窄屏使用胶囊圆边，显示文字按钮的桌面布局（768px 起）使用小圆角矩形。

Editor 点击步骤中部或变量名称区域进入编辑，行末为带确认的删除按钮；变量值仍可直接修改。

编辑弹窗和设置统一标签在左、输入在右，输入及选择控件使用带边框的样式；名称或步骤类型在最上方，说明置于最后、操作区之前。分组仅使用标题与留白，不使用分割线。步骤类型按调用、变量、控制、文本、数学、逻辑分组并支持搜索；每种节点有独立图标，类型选择器与步骤列表共用，颜色按类别区分。工作台变量输入也使用带边框的样式。分组标题统一加粗，字段标签使用较小的常规字重。变量与步骤仅从列表右侧删除；变量弹窗编辑名称、用途、默认值和说明；外部变量栏始终编辑运行值，不写回默认值。

默认值持久化在流程定义；运行值只保留在当前 Editor。完成或失败后保留运行值，再次运行或单步从这些值开始；仅点击重置恢复默认值。修改默认值不覆盖已有运行值；编辑步骤或变量定义会清除旧执行记录，但保留同名变量的运行值。暂停期间改值通过 Core setFields 更新当前运行，继续执行不重置进度。拖动手柄各状态保持透明底色。

运行值标题与“重置到默认值”“设置为默认值”按钮同排显示。运行值与默认值一致时隐藏两个按钮；设置为默认值将已声明变量的当前 JSON 值写入流程默认值，未设置值移除对应默认值，非 JSON 值不支持保存为默认值。

Editor 对未满足对话约定的流程显示“设置为对话”，补齐 chatIn、threadId 输入及 chatOut 输出，保留已有字段配置和步骤。满足约定后隐藏该按钮；此操作仅配置对话入口，不自动添加模型调用或改写回答逻辑。

顶部导航使用分段切换样式：浅灰胶囊底槽、白色选中块和轻边框阴影，未选中项透明。中文名称为对话、流程库、编辑器；桌面显示图标和文字，小屏（小于 768px）仅显示图标并保留无障碍名称。底部运行工具栏保留原操作按钮样式。

2026-10-03 调用目标统一：`call.target` 为名称字符串，删除 kind/key/id 对象；开发期继续 schemaVersion 1。Core 从当前 LoadedFlow 的 imports 与宿主函数注册表解析，重名一律运行前报错；显示名称不作为跨文件身份。CLI inspect.references 使用 `{target, path}`。旧协议文件需显式修改，Editor 只对已有浏览器存储数据迁移目标格式。

Editor 调用目标统一搜索内置工具和 Library 流程，不再选择调用类型。选择 Library 流程时保存局部别名与 `library:<文档ID>` imports，重名显示名分配不同别名，流程改名不影响已保存引用；新建/改名/上传不得使用内置工具名。Editor 和 Agent 对话通过 Core LoadedFlow 图执行 Library 子流程，使用其 input/output 字段契约；每次运行固定依赖快照，删除依赖明确报错，循环依赖由 Core 调用深度限制保护。步骤列表保留父调用执行前后结果，不把子流程同路径节点误标为父步骤。外部文件/HTTPS imports 仍不支持；导出文件的 library: 引用仅能在拥有相应文档的浏览器库中解析，CLI 使用前需替换为文件或 HTTPS 来源。

Library 新建、改名、上传及保存统一要求流程名称唯一（忽略首尾空格，区分大小写），按文档 ID 排除自身。保存检查与写入串行化，支持 Web Locks 的浏览器同时覆盖多标签页。历史同名文档保留供用户改名，不自动删除或重命名。此限制属于 Library 管理，不改变 Core 的局部 imports 作用域规则。
