# 认识 Agent Plan

Agent Plan 用简单、顺序的步骤组织工具和 AI 调用。你可以先使用预设，再展开内部步骤，查看输入、变量、工具结果和错误。流程只有一种执行语义，网页和 CLI 都由 Core 执行。

## 推荐阅读路线

第一次使用，从 [快速入门](quick-start.md) 开始，不配置模型也能运行。随后读 [文件库与编辑器](workspace.md)，了解保存和运行的区别。

编写流程，读 [流程结构与全部节点](flows/language.md)、[变量与数据路径](flows/operands.md)、[子流程与调用](flows/subflows.md)。编写代码，再读 [脚本开发](scripts/development.md)。

开发 Agent，先查 [工具参考](tools/reference.md)，再读 [模型与工具循环](agents/models.md) 和 [存储与记忆](agents/storage.md)。出错时查 [调试](debugging/guide.md)；使用命令行时查 [CLI](cli/guide.md)。

## 三个工作界面

| 界面 | 用途 |
| --- | --- |
| 对话 | 与内置助手或具备聊天接口的用户流程对话 |
| Library 文件库 | 保存流程、脚本、配置和其他原始文件，管理目录与工程包 |
| Editor 编辑器 | 用步骤列表、嵌套块和变量表单编辑流程，运行与逐步调试 |

Document 是应用自带的手册。它不属于用户文件库；人类阅读界面和助手 `project.docs` 使用同一套章节。章节有稳定 ID、源路径与手册版本，正文按需加载。

## 流程 工具 脚本

流程是 JSON/YAML 文档，定义变量和步骤。工具是宿主注册的函数，通过 `call` 调用。子流程也是调用目标，通过 `imports` 指定来源。脚本通过工具 `script.run` 执行 JavaScript，适合步骤节点不方便表达的数据处理。

流程名称用于展示，导入别名或工具名称用于查找。不要用名称猜测文件路径。数据流由输入、输出映射明确表达；分组只改变展示，不创建新的变量作用域。

## 当前能力

网页支持 IndexedDB 文件库、源码与表单编辑、流程运行、单步调试、模型调用和助手文件操作。CLI 支持磁盘及 HTTP(S) 流程加载、校验、运行、trace、工具与脚本执行。

内置助手可以修改文件、检查并运行已保存流程。它不能直接读取未保存的编辑器草稿，也不能控制同一现场的单步调试。CLI 尚未注册网页的 `workspace.*`、`project.*`、`flow.*` 助手工具。

浏览器文件库不自动同步磁盘，trace 不能恢复运行。独立发布的嵌入 SDK、共享远程调试会话、MCP 和原生封装不属于当前功能。详细边界见 [架构](architecture.md)。
