# Runtime 设计与接口

Runtime 保存一次运行的当前字段和执行进度。单步执行是基础，一次运行到底复用相同的执行逻辑。Core 不保存历史，不为返回状态制作快照。

## 1. 接口范围

```ts
const runtime = createRuntime(flow, { count: 0 }, { maxIterations: 1000 });

await runtime.step();
runtime.setFields({ count: 2 });
const state = await runtime.run();
runtime.reset();
runtime.reset({ count: 5 });
```

| 方法 | 行为 |
| --- | --- |
| `step()` | 异步推进共享调用栈顶一步，返回实际执行实例的 `{ state, event }` |
| `run()` | 异步从当前位置执行到本实例结束（包括其后代），返回本实例的 `state` |
| `getState()` | 返回当前状态及字段容器的只读视图，不复制数据；字段值为 `unknown` |
| `getStack()` | 返回从根到当前执行实例的实时只读 runtime 数组 |
| `setFields(values)` | 修改已配置或从步骤中自动收集的字段，保留执行位置，返回状态 |
| `reset(inputs?)` | 仅根可用：恢复全部初值、覆盖本次提供的输入、清空进度和错误，使旧子实例失效，返回 `ready` 状态 |

不提供 `resetFields()`、`startAt`、跳转、重试、暂停、取消或快照恢复。`reset()` 不重新应用创建时的输入；不传参数就只使用初值。

## 2. 状态与单步信息

状态包含 `invocationId`、`flowName`、可选 `source`、`depth`、`status`（`ready`、`running`、`waiting`、`completed`、`failed`、`invalidated`）、`busy`、`fields`、`nextStepPath`，完成后包含 `output`，失败后包含 `error`。子流程调用规则见 [子流程文档](subflows.md)。

`running` 表示运行已开始但未结束，单步间也保持此状态；是否正在执行由 `busy` 表示。创建和重置后为 `ready`，空流程在首次 `step()` 或 `run()` 时完成。

状态对象始终是同一个实时视图，不能当作历史快照。`step()` 的事件记录实际执行实例、流程名称与来源、本步路径和类型；控制步骤记录判断结果和分支，调用步骤记录新子实例标识，失败事件附带错误。不保存完整输入、字段前后值或事件历史。已完成或失败实例再次 `step()` 返回 `event: null`，`run()` 返回已有终态，不推进其他实例；失效实例拒绝执行。

状态和字段容器的只读类型仅是编译期约束，不使用运行时冻结或代理。任意字段值可能是共享对象，不承诺深度只读。调用方通过方法替换字段；需要历史时由外层自行复制。重置会替换 `fields` 容器，调用方应从状态视图读取当前容器，不缓存旧的 `fields` 引用。

创建时复制流程定义，初始化和重置时复制 JSON 初值。运行输入、外部赋值、`set` 及调用输出均按引用传递值，只保持字段和参数容器独立。共享对象的内部修改相互可见，core 不制作快照。详细规则见 [外部函数与参数文档](functions.md)。

## 3. 一步的含义

- 普通节点：读取输入、计算并提交结果，算一步。
- `if`：判断条件并选分支，算一步，分支中的节点随后逐步执行。
- `while`：每次判断条件算一步，循环体的节点随后逐步执行；退出判断也算一步。
- `call`：传参并创建子流程、入栈算一步；之后逐步进入子流程，最后一步完成后自动回写输出并返回。空子流程在调用这一步完成。
- `call` 的 `function` 目标：等待同步或异步函数返回并提交输出算一步，不增加调用栈实例。
- 执行栈进出不是额外的用户步骤。最后一步完成后立即组装输出，不需要 Return。
- 循环只读取条件字段，不重新计算比较；循环体需要自行更新条件。

错误和下一步位置使用 `steps[1].then[0].body[1]` 这样的流程内路径，结合调用实例标识定位。调用栈可查看；各流程内部的控制帧和循环计数保留在内核内部，不作为可恢复状态导出。

## 4. 忙碌、修改与错误

`step()` 从调用到 Promise 完成、`run()` 从调用到目标实例完成期间均占用共享忙碌标志。父子任意层新的 `step()`、`run()`、`setFields()`、`reset()` 会以 `RUNTIME_BUSY` 拒绝；状态和栈仍可查看。不排队，不重复执行，不影响已经发起的调用。

初始化时递归扫描全部节点及分支、循环，收集读写及条件中出现的字段名。未在 `fields` 配置的字段自动以 `undefined` 初始化，默认为内部字段；不检查拼写。步骤输入支持 JSON 固定值、`$` 路径与 `$$` 转义；递归收集其中引用的根字段。初值和宿主输入保持原样，完整规则见 [变量、对象与数组](operands.md)。

`setFields()` 在 `ready`、`running` 或 `waiting` 且不忙碌时使用，允许修改本实例的输入、输出和内部字段，包括自动收集的字段。终态需先从根 `reset()`。既没有配置、也没有出现在步骤中的字段仍属于未知字段；修改时不动态创建这类字段。值可为任意类型，一批字段名全部校验成功后才一起提交。

创建和重置的输入只能包含 `input: true` 的同名字段，未知字段或非输入字段报错。缺失参数保留初值，显式 `null` 或 `undefined` 都覆盖初值。无效重置不改变原有状态。

自动收集的字段也会在 `reset()` 时恢复为 `undefined`，不改变原始流程定义。未声明不等于对外输入，若要通过创建或重置传参，需要显式配置 `input: true`。

调用错误（忙碌、非法修改、非法输入）抛出 `RuntimeError`，不把运行置为失败。节点执行错误、循环超限则写入 `state.error`，状态变为 `failed`，`step()` / `run()` 正常返回该失败状态。之前成功的写入保留；普通对象和数组的目标写入先检查再提交，检查失败不写入。宿主函数的外部副作用及其自行修改的共享对象不回滚，Proxy 等带宿主陷阱的对象不保证事务性。失败后必须重置才能重新执行。

默认每个循环每次进入最多执行 1,000 轮，可用 `maxIterations` 配置为正安全整数。计数跨多次 `step()` 保留，修改字段不清零；内层循环每次重新进入有自己的计数。恰好执行到上限后条件为假可正常退出，仍为真才报错。

## 5. 默认节点及自动转换

数学节点 `add`、`subtract`、`multiply`、`divide` 和大小比较按数字转换输入：数字字符串转数字，`true` / `false` 转 `1` / `0`，`undefined`、`null`、空串、空白串转 `0`。无法转换的文本、数组、对象报错。除零、非有限结果报错。转换不修改源字段。

`equal` / `notEqual`：相同类型的基础值直接比较；不同类型的非 null 基础值若均可转数字，按数字比较，否则不相等；`null` 只等于 `null`，`undefined` 只等于 `undefined`。普通 JSON 对象和数组按内容比较，对象键顺序不影响结果，容器内部不做类型转换。其他对象和函数按引用比较。

条件及逻辑运算采用 JavaScript 真假规则。`and` / `or` 至少一个输入，`not` 一个输入，结果统一为布尔值。空数组、空对象为真。

`template`（文本模板）使用原样字符串 `template` 和写入目标 `output`，替代旧 `concat` 节点。正文不是 Operand，不自动解析 JSON/YAML。

```json
{ "type": "template", "template": "你好，$user.name$！\n价格：$$99", "output": "$result" }
```

- `$path$` 引用变量，支持对象属性和数组索引，路径安全规则与普通引用一致；`$$` 输出字面量 `$`。`$$name$$` 输出原文 `$name$`。
- 原文的空格、换行、缩进保持不变。替换只执行一次，变量值内的模板符号不继续解析。
- 字符串原样插入；数字、布尔值、null 显示文字；对象、数组用 YAML（不自动折行）。独占一行的占位符会将该行缩进补到插入值的后续各行。行内多行插入不补缩进。
- 非法或未闭合引用在校验时报错；缺失或未赋值变量替换为空字符串。非 JSON、循环值也需要显式转换。
- 空正文得到空字符串。引用根仍自动收集为字段；转换只作用于当前节点，不修改变量的原始值。
- 不保证插入后形成合法 YAML：模板是文本替换；需要结构化数据时应使用对象操作节点。数据本身不保存原始 YAML 的注释或引号样式。

## 6. 验证范围

实现需验证嵌套分支与循环、跨流程单步与运行范围、共享忙碌保护、原子字段修改、根重置与旧实例失效、输入输出隔离、循环和调用深度保护、错误调用链、转换规则及非法 JSON / 流程结构。不引入模型或工具 SDK。

未设置值（undefined）在数学运算和大小比较中按 0 使用，在文本模板中按空字符串使用。相等比较、存储和输入/输出继续保留原始值语义；除数转换成 0 后仍报除零错误，非法路径和不可转换数据仍报错。

### Step groups

`type: group` is a transparent sequence. `step()` skips empty groups and executes the next real operation; group wrappers emit no events. `nextStepPath` and errors use nested `.steps[index]` paths. `name`, `description`, and `collapsed` stay in the distributed definition. See [inline groups](groups-and-tools.md).

## 敏感字段元数据

字段可声明 `sensitive: true`（布尔值，默认 false）。它只提供宿主显示与导出的提示，不改变初值、字段引用身份、输入输出和执行结果，也不自动传播到其他字段。

`runtime.getSensitiveFields()` 返回当前实例明确标记的字段名。`redactFields(values, names)` 返回浅层显示副本，标记项替换为 `[sensitive]`，不修改原值。`withoutSensitiveInitials(flow)` 保留字段及分组结构，移除敏感字段初值，供宿主导出使用。`redactFailure(error, names)` 在存在敏感字段时隐藏错误消息，保留位置及代码。

Core 不提供凭证存储或访问限制，宿主负责应用遮挡规则。环境读取工具由宿主注册，同一运行的子流程复用函数注册表；不是流程变量的全局作用域。
