# Agent Plan Editor

React + TypeScript + Vite 的响应式编辑器，复用 Core、AI 与存储包。

```sh
pnpm install
pnpm editor
```

生产构建可运行根目录 `pnpm build`；单独构建 Editor 前需先构建 core、ai、storage。

## 三个界面

- **Agent**：正常消息对话、发送/停止；抽屉管理所有对话，设置集中到抽屉底部入口。执行选中的流程，将消息写入 `chatIn` 输入，并将 `chatOut` 输出显示为回复：字符串渲染 Markdown，数字、布尔值、null、对象和数组显示为 YAML 代码块。只有 `fields.chatOut` 开启 output 的流程才会出现在 Agent 选择器中，其他流程在 Editor 调试。
- **Library**：平铺流程卡片，支持搜索、新建、上传 JSON/YAML（每个文件最多 5 MB）、下载 YAML、重命名、确认删除。每次上传新建独立记录，同名文件不会覆盖已有流程；导入内容通过 Core 校验，外部 imports 保留但暂不能在浏览器执行。
- **Editor**：步骤列表、参数表单和变量面板。参数采用名称 + 输入栏，自动推断数字、布尔值、JSON/YAML 对象和列表；调用参数按名称逐行显示。支持弹窗新增/编辑、列表确认删除、手柄拖拽排序、嵌套分支、一次修改撤销和单步测试；变量在上，步骤在下，运行工具栏固定底部。

步骤点击“应用步骤”后写入 Library；有效的变量设置自动保存，列表运行值只影响当前调试，不写入流程默认值，不再提供保存变量按钮。无效输入明确报错，不称为已保存。变量名变更不自动重写步骤引用。运行数据直接复用变量面板，暂停时修改值通过 Core setFields 生效，不重置运行进度；最多保留 300 条步骤记录，每次连续调试最多推进 2000 步后暂停。Agent 页超过 2000 步则失败，避免对话无限等待。

## 默认本地 Agent

Agent 的内置入口与首次 Library 模板使用简单的 hello Agent Plan 流程，仅包含 chatIn、memoryKey、chatOut 三个变量和设置 chatOut 的一步；不调用模型、不自动读写记忆。

新建流程从同一模板开始，但使用独立记忆 key。Agent 的“新对话”创建独立 thread，保留旧记录，并为 `memoryKey` 提供独立初值。其他硬编码 key 的自定义记忆由用户流程管理，Editor 调试仍使用流程原始 key。

## 数据保存

- 流程定义：IndexedDB `agent-plan-library`，按稳定 ID 保存；重命名不改变 ID。
- 对话展示记录：IndexedDB `agent-plan-conversations`，按流程 ID 保存；展示历史不等于模型实际接收的记忆范围。
- 流程的通用存储：原有 `agent-plan-storage`，通过 key 分组。
- 模型凭据、下载许可：仅当前页面内存，刷新后重新设置，不写入导出的流程。

页面刷新后已保存流程、对话和记忆仍保留；执行现场不恢复。数据属于当前浏览器和站点，清理站点数据会丢失。重要流程请下载备份；尚无 Git 同步、文件夹关联、多设备同步或通用存储管理页面。

## 工具与限制

已注册 `local.generate`、`openai.generate`、`anthropic.generate`、`storage.read/write/delete/list`、`tokens.count`。在 Editor 添加调用步骤，选择工具名称后编辑参数。使用方法见 [AI 工具](../agent-plan-ai/README.md) 和 [存储与计数](../docs/storage-and-tokens.md)。

模型调用仍复用共享工具；本地模型在 Worker 中运行。停止调用无法回滚之前已发生的存储或外部副作用。外部子流程加载、浏览器 runScript、通用工具加载和 Agent 工具循环仍未实现。当前的 Agent 对话页运行用户流程，不是操作编辑器的内置助手。

## 验证

`pnpm --filter agent-plan-editor test`、`pnpm --filter agent-plan-editor build`。自动测试覆盖 JSON/YAML 导入、错误文件拒绝、默认对话入口、thread 记忆键隔离、步骤调试记录。真实 Chromium 已验证上传、重命名、下载、刷新持久化、流程驱动对话、步骤及对象变量表单编辑，以及 390px 下三页无横向溢出；不等于真实手机 GPU 验证。


### 多对话与节点展示（2026-10-02）

Agent 支持新建和切换多个 thread，每个流程的会话列表、当前选择和聊天记录保存在浏览器中。新对话不删除旧记录。约定 `memoryKey` 字段为对话记忆位置，Agent 运行时为每个 thread 提供独立初值；硬编码存储 key 的自定义流程仍共享该 key。已有单会话记录迁移为第一个 thread，保留原记忆位置。Editor 调试仍使用流程原始初值。

Library 默认导出可读 YAML，仍兼容 JSON/YAML 上传。19 种基础节点按数据、文本、计算、判断、控制和调用六类着色；卡片优先显示节点名称或调用目标，说明作为辅助文本，参数与详细结果按需打开。


对话流程最小示例见 [chat-echo.yaml](../examples/chat-echo.yaml)。chatIn 接收消息，chatOut 返回回复，无需新增 Core 节点。已有浏览器流程的旧 text 或 prompt/answer 对话约定通过普通 set 步骤迁移，保留原逻辑。

界面遵循信息最小化：Agent 直接选择对话流程和 thread；Library 使用图标操作及名称省略组件；Editor 显示短节点名、类别图标和输入/输出摘要，点击步骤名称打开输入/输出参数与说明弹窗，删除在列表右侧操作。操作图标提供无障碍标签，主要按钮保持 44px 触控目标。


### 参数与单步变量（2026-10-03）

- 参数名在左，编辑栏在右，不再手选类型。`12` 为数字、`true` 为布尔值、`null` 为空值，JSON/YAML 自动解析；`"123"` 保留为字符串。普通文本保留原有空格和换行。步骤中的 `$path` / `$$text` 仍遵循 Core 引用/转义规则；变量初值和调试值保持字面量。
- 变量栏留空表示未设置，填写 `""` 表示空字符串；步骤参数留空表示空字符串。结构语法错误、重复 YAML key、非有限数字等明确报错，不能带着错误保存或运行。
- 变量设置（名称、默认值、说明、输入/输出标记）使用弹窗；有效修改自动保存。列表内输入只修改运行值，删除操作在列表右侧。
- 单步结束后，同一变量面板显示当前值；暂停时改值立即调用 Core `setFields`，下一步使用新值，不改变已记录的步骤快照或流程初始值。运行中禁止修改；完成/失败后可以直接改运行值或再次运行，重置才恢复默认值。保存步骤或变量定义清除进度并保留同名变量的运行值。
- 非 JSON 运行值和未声明的动态变量只读，不把展示摘要伪装成可恢复数据。变量值、执行现场不持久化为可恢复会话。


### Mantine 与 i18n

基础 UI 使用 `@mantine/core` / `@mantine/hooks`（9.6.3），主题见 `src/theme.ts`，组件通过入口 `MantineProvider` 提供。基于现有 Vite 项目接入，不依赖额外后台或 Tailwind；保留产品布局 CSS，菜单、弹层、焦点控制等优先复用组件库。设置使用独立页面，分组直接展开，通过返回按钮回到原界面。

国际化使用 `i18next` 26.4.2 与 `react-i18next` 17.0.15。默认简体中文，可在设置中切换 English；偏好记录在 localStorage 的 `agent-plan.language`，存储不可用时仍能在当前页面切换。语言资源位于 `src/locales/zh-CN.json` 和 `src/locales/en.json`，首版随应用打包，不发起语言资源网络请求。

新增 UI 文案使用 `tr`，当前使用中文源文案作为 key，避免在代码里拼接翻译句子；动态值使用 `{{name}}` / `{{count}}`。组件若脱离 App 单独挂载，应使用 `useTranslation` 订阅语言变更。新增语言时补资源、supportedLngs 和选择入口。不得翻译用户流程内容或协议字段；工具/模型原始消息保持原文。语言切换保留表单草稿与运行状态。

这些依赖均为 MIT 许可；安装时已核对 React 19.3 和 TypeScript 7 的 peerDependencies。测试覆盖资源键与插值变量一致性、语言切换和用户工具标识保真。

### 抽屉与触摸操作（2026-10-03）

- 顶部悬浮标签切换 Agent / Library / Editor；左侧抽屉列出各对话流程的 thread，点击回到 Agent。顶部不再放用户/设置入口，设置仅从抽屉底部进入。
- 手机抽屉通过按钮打开/关闭，点击遮罩也可关闭；滑动手势已移除，后续再设计。桌面抽屉展开时让出主页面空间。
- 输入框上方输入文字，下方选择 Agent 与发送/停止；多模态和语音尚未实现，不展示可用按钮。
- 步骤和变量用 dnd-kit 手柄支持鼠标、触摸与键盘排序；嵌套步骤在各自分支内排序，不跨分支拖动。使用 `@dnd-kit/core` 6.3.1、`sortable` 10.0.0、`utilities` 3.2.2（MIT，React peer >=16.8，包含 ESM 构建），避免自行实现拖拽碰撞和键盘排序。
- 删除流程仅删除 Library 定义，保留既有对话/通用存储；最后一个流程删除后库保持为空，内置 Agent 仍可使用。
- 浏览器验证覆盖弹窗增删、自动保存与刷新、暂停改值、对话切换、键盘/触摸排序与抽屉手势；不代表真实 iOS/Android 或手机模型推理验证。

### 设置与对话管理补充（2026-10-03）

设置只从抽屉底部进入，桌面和手机均为带返回入口的独立页面，采用常规、本地模型、OpenAI、Anthropic 分组，不折叠内容；返回保留原页面与草稿。抽屉使用侧栏折叠图标。

每条 thread 右侧提供删除图标，确认后持久化删除聊天记录；不删除流程或工具存储。删除当前 thread 时选择剩余 thread；删掉最后一条 thread 后保留空列表；显式新建或首次发送消息时才创建新的 thread 与 memoryKey。运行中禁止删除。

### 紧凑列表与删除修正（2026-10-03）

Library 搜索在左，数量/上传/新建在右，共用一行；手机隐藏数量和按钮文字，保留圆形图标按钮。流程标题右侧显示类型标签，卡片中部预留说明，右下角集中显示操作。点击卡片进入 Editor；名称与说明通过操作按钮打开弹窗修改。变量区取消整体大卡片，变量以无卡片底板的紧凑行展示，保留拖拽、内联值与弹窗设置。对话行整行悬停着色；确认删除弹窗层级高于手机抽屉。纯图标按钮使用圆形底板，颜色与交互含义不变。

对话输入框占满输入区并左对齐；右侧 Agent 选择统一使用带搜索的组件弹窗。Library 桌面搜索限制宽度，上传/新建按钮默认透明，卡片两行之间不加分割线并保持紧凑间距。步骤拖动手柄放在步骤卡片内部，底部运行工具栏在手机与窄屏使用胶囊圆边，显示文字按钮的桌面布局（768px 起）使用小圆角矩形。

Editor 点击步骤中部或变量名称区域进入编辑，行末为带确认的删除按钮；变量值仍可直接修改。

编辑弹窗和设置统一标签在左、输入在右，输入及选择控件使用带边框的样式；名称或步骤类型在最上方，说明置于最后、操作区之前。分组仅使用标题与留白，不使用分割线。步骤类型按调用、变量、控制、文本、数学、逻辑分组并支持搜索；每种节点有独立图标，类型选择器与步骤列表共用，颜色按类别区分。工作台变量输入也使用带边框的样式。分组标题统一加粗，字段标签使用较小的常规字重。变量与步骤仅从列表右侧删除；变量弹窗编辑名称、用途、默认值和说明；外部变量栏始终编辑运行值，不写回默认值。

默认值持久化在流程定义；运行值只保留在当前 Editor。完成或失败后保留运行值，再次运行或单步从这些值开始；仅点击重置恢复默认值。修改默认值不覆盖已有运行值；编辑步骤或变量定义会清除旧执行记录，但保留同名变量的运行值。暂停期间改值通过 Core setFields 更新当前运行，继续执行不重置进度。拖动手柄各状态保持透明底色。

运行值标题与“重置到默认值”“设置为默认值”按钮同排显示。运行值与默认值一致时隐藏两个按钮；设置为默认值将已声明变量的当前 JSON 值写入流程默认值，未设置值移除对应默认值，非 JSON 值不支持保存为默认值。

Editor 对未满足对话约定的流程显示“设置为对话”，补齐 chatIn、memoryKey 输入及 chatOut 输出，保留已有字段配置和步骤。满足约定后隐藏该按钮；此操作仅配置对话入口，不自动添加模型调用或改写回答逻辑。

顶部导航与底部运行工具栏共用视觉规范：中文名称为对话、流程库、编辑器；桌面显示图标和文字，小屏（小于 768px）仅显示图标并保留无障碍名称。选中项深绿填充，小屏胶囊容器、桌面小圆角矩形。

步骤输入与输出支持变量联想：短单行名称（最多 48 字符）按已有变量筛选，选择补齐 `$`，无匹配时提供新增；多行、长文本、JSON/YAML、数字和 `$$` 转义不显示联想。新增引用在应用步骤时由 Core 收集为流程变量，取消不创建变量。输出框固定显示 `$` 前缀，草稿变量名默认留空，选择建议自动填入名称；输入用 Core 校验，非法内容保留并提示，阻止提交以便修正。调用输出留空表示不保存，必需写入目标的节点应用前仍需填写。
